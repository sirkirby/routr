## Upgrading from 0.8.3

No configuration change is needed, and none of your settings change: subscriptions, models, effort, reserves,
decision models, update channel and telemetry are read as before.

There is one new, optional setting: **OpenTelemetry export**, off unless you turn it on. Run `routr setup` if you want
to review it. Setup asks one new question, whether to send OpenTelemetry to an endpoint of yours, and the answer
defaults to no. Every other choice is kept as it is, and `routr setup --yes` never turns export on. If you don't use
an OpenTelemetry backend, there is nothing to do.

The update reinstalls routr's skills, and the guides changed in this release:
- the setup guide has the export commands;
- the harness reference has the lead-session variables routr removes, and the trace context each harness reads;
- the orchestrator guide has `--lead-session`.

An agent that already loaded routr reads the older guides until it rereads the skill or starts a new session.

**If your lead agent runs with OpenTelemetry trace context** (for example, Claude Code with its own tracing on gives
its shell commands `TRACEPARENT`): workers now get the `TRACEPARENT`, `TRACESTATE` and `BAGGAGE` routr was started
with, unchanged while export is off. With export on, routr's launch span takes `TRACEPARENT`'s place (below). Before,
a headless worker inherited them unchecked, and a pane worker got whatever the herdr server had. Nothing else about
launching changes.

**If you run `routr launch --worktree` in herdr:** the worker now runs in a new pane split from the one herdr opens
with the worktree, and that first pane is closed, so the worker's pane can get routr's trace context. Launch's `pane`
is the new pane; `routr cleanup` works as before.

## Highlights

- **OpenTelemetry export, to your own endpoint.**
  - Turn it on with `routr setup --otel-endpoint <url>`: HTTPS, or HTTP on your own machine. Set any auth headers
    with `routr key set otel-headers`, which stores them as a secret.
  - routr then sends OTLP/HTTP JSON:
    - **traces** of its commands (`dispatch`, `launch`, `send`, `wait`, `cleanup`, `record` and the rest) and of
      each headless worker turn;
    - **logs** of fixed events: a worker needing input, a warning, a failed usage read, a worker changing state;
    - one **gauge**, `routr.subscription.headroom`, for each subscription's usage window.
  - A detached sender delivers them from a local queue and retries with backoff, so no command waits on the network.
  - `routr doctor` and `routr setup --show` report its status. `routr setup --otel-off` turns it off.
  - Lineage follows OpenTelemetry's own rules: the launch is a child of the trace context routr was started in, the
    worker gets the launch span as its `TRACEPARENT`, headless turns nest under the launch, and later commands link
    to it. The lead's session id is `routr.lead.session_id`, read from the lead harness's own variable, or from
    `--lead-session <id>` on `dispatch`, `subagent` and `launch`.
  - Never sent: briefs, reports, prompts, replies, pane screens, keys, header values, baggage values, absolute paths.
  - Every span, attribute, log event and the gauge is in
    [docs/opentelemetry.md](https://github.com/sirkirby/routr/blob/main/docs/opentelemetry.md), pinned to
    OpenTelemetry's GenAI semantic conventions (commit `9ffc7e00`, core conventions 1.44.0).
  - It is separate from routr's anonymous telemetry, with its own setting, consent and state. An agent never turns
    it on for you.
- **Trace context reaches every worker.** routr passes `TRACEPARENT`, `TRACESTATE` and `BAGGAGE` to the workers it
  starts: headless workers on every turn, a pane it splits, and a worktree's pane. Each one it does not pass is set
  empty there, so a worker never picks up a stale trace from the herdr server. An existing `--pane` or an adopted
  agent gets none, and launch says so. Output shows `<forwarded>`, never a value.
- **The lead's session no longer leaks into workers.** Workers and usage reads used to inherit the lead agent's
  session variables from Codex, Cursor, Antigravity and Kiro; before, only Claude Code's and Codex's thread id were
  removed. They are now removed too, including Cursor's sudo-prompt secret, and so are herdr's pane variables. The
  harness reference lists every name.
- **Fixes:**
  - On Windows, launch no longer times out when PowerShell's prompt is wider than the worker's pane, as with a long
    worktree path in a half-width pane.
  - On Windows, a folder name with a curly quote (`Chris’s`) reaches a PowerShell pane exactly; a cmd pane is refused
    a path with `%` or `!` instead of getting it mangled.
  - Launch and Cursor's usage read no longer fail when herdr briefly can't report a new pane's processes.
  - On Windows, a headless worker's saved state is far less likely to be missing for a moment while another routr
    command reads it, which could make `routr workers` show a finished worker as starting.
  - routr's shared file lock (the updater, headless workers, the background usage refresh) holds when a process
    pauses or crashes. A background usage refresh that resumes late no longer overwrites a newer reading.

## Verification

Measured, all on 2026-10-26 unless noted:
- **Tests:** `bun test` on macOS, Linux and Windows.
- **`bun run smoke:carriers`:** live in herdr 0.9.5. It checks routr's own split code, carriers at their size
  limits with hostile characters, a worktree pane, and the carrier left out arriving empty.
  - macOS (zsh): passes, including the started agent's own environment.
  - Windows 11 ARM64 (PowerShell 5.1, herdr's x64 build): passes. The agent's environment can't be read on Windows,
    so that part is macOS only. This run found the wrapped-prompt bug fixed above.
- **`bun run smoke:otel`:** fixture harnesses, no subscription. Each run: 15 spans, 8 log records, the gauge, and a
  sender killed mid-delivery recovering its batch.
  - macOS and Windows 11: pass.
  - Every batch was also accepted and decoded by the reference OpenTelemetry Collector (contrib 0.120.1 and 0.136.0,
    OTLP/HTTP receiver, debug exporter), with trace ids, parentage, typed attributes, the schema URL and, on 0.136.0,
    each log record's event name intact.
- **Protocol checks:** Codex 0.164.0 and Kiro 2.34.0 accept the trace fields routr sends in their protocols, checked
  with no prompt sent (2026-10-25).
- **Live lineage:** a real reviewer worker launched with a marker `TRACEPARENT` received it (macOS, 2026-10-25).
- **Review:** every pull request was reviewed by a routr worker on another model family, and the feature as a whole
  by one that had seen none of it. Its findings (the lock under a paused process, the late usage refresh,
  concurrent sends, span timing, setup and docs wording) were fixed before this release.

Not measured:
- a vendor OpenTelemetry backend (only the reference Collector);
- Linux in a live herdr session (CI tests only);
- headless Kiro and Antigravity turns traced end to end with the real harness (their fixtures and protocol checks
  only).

## CLI and JSON compatibility

No field or flag was removed or renamed. Additions:
- **New flags:**
  - `setup --otel-endpoint <url>` and `--otel-off`;
  - `key set otel-headers`;
  - `--lead-session <id>` on `dispatch`, `subagent` and `launch`.
- **`launch`:** `start.env` lists each trace-context carrier passed, as `"<forwarded>"`. `ran` and `would_run` show
  the split's `--env NAME=<forwarded>`, and for `--worktree` the split and the close of the root pane.
- **`workers`:** `carriers_withheld`, only when a saved carrier is now outside routr's limits.
- **`doctor` and `setup --show`:** an `otel` status object.
- **`uninstall`:** `otel_sender_running`, and on Windows `kept_binary`.
- **New warnings:**
  - a trace-context carrier withheld or not passed;
  - an ignored `--lead-session`.
