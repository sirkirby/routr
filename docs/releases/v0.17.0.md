## Every worker span names that worker's own session

This applies only if you turned on OpenTelemetry export (`routr setup --otel-endpoint`). Export stays off unless you configure it.

Every `invoke_agent` span now carries the worker's own harness session id as `gen_ai.conversation.id`:
- a pane or Herdr app worker's launch task;
- a Herdr app worker's `routr send` message;
- a headless turn.

The command span above it still carries the lead's id. A receiver that reads only standard attributes can tie a lead to each worker from that pair, without matching by repository, branch or time.

routr names only an id it can prove is that worker's, never a match by time, folder or branch:

- **Claude Code**, in a pane or the Herdr app: routr starts it with a new id in `--session-id`.
- **Cursor**, in the Herdr app: routr asks `cursor-agent create-chat` for a chat in the worker's own folder and private config, and starts the worker in it with `--resume`. This makes no model request.
- **Codex and Antigravity**, in the Herdr app: a worker's first message names its prompt file, which is named for that launch alone. routr finds the one session whose own record holds exactly that message: Codex's rollout, or Antigravity's conversation transcript. If two sessions hold it, routr names neither.
- **Codex, Cursor and Antigravity**, in a herdr pane: herdr's report from the harness's hook, as before. A launch that exports a span now waits up to 20 seconds for that report instead of reading it once.
- **Kiro**, in a pane or the Herdr app: routr has no id it can prove, so it names none.

When routr has no id, the span says why in a new attribute, `routr.conversation.missing`:
- `no_source`: the harness keeps no id routr can prove;
- `not_assigned`: Cursor's `create-chat` gave none;
- `not_found`: the harness had not written it yet. This includes a headless turn that ended before its harness named its session.

A launch that exports a span waits up to 20 seconds for an id the harness has not written yet. Other launches don't wait: `workers`, `wait` and `send` find the id later.

One limit: when a harness moves a running worker to a new session (Claude Code's `/clear`, Codex's `/new`), later spans still name the session it started with. routr cannot see that move.

## `routr workers` shows a Herdr app worker's session

A Herdr app worker's row in `routr workers` and `routr wait`, and its launch answer's `worker`, now show `session`, the harness's own session id. When it is null, `session_missing` gives one of the codes above. A headless worker already showed its `session`.

## Upgrading from 0.16.0

No setup is needed, and your settings do not change. The update reinstalls routr's skills; the harness reference now lists how each harness's session id is known. An agent that already loaded routr reads the older guide until it reads it again or starts a new session.

Workers launched by 0.16.0 keep running and are cleaned up as before. Their run folder holds `prompt.md`, not the new `prompt-<id>.md`, so `routr workers` shows no `session` for a Codex or Antigravity worker launched before the update.

A Herdr app worker's run folder now also holds `session.json` once its Codex or Antigravity session is found. `cleanup --worker` removes it with the folder.

## JSON and output changes

- A Herdr app worker's launch `worker`, and its `workers` and `wait` rows, add `session` and, when that is null, `session_missing`. No field is removed or renamed.
- A Herdr app worker's prompt file is now `prompt-<record id>.md` in its run folder; it was `prompt.md`.
- Exported OpenTelemetry adds `routr.conversation.missing` and fills `gen_ai.conversation.id` on more `invoke_agent` spans. `docs/opentelemetry.md` lists every span and attribute.

## How much of this was run

- **Tests:** `bun test` passes on macOS, Linux and Windows CI. They cover:
  - each harness's id source, including another worker's first message, an earlier session, two matching sessions and an id of the wrong shape;
  - a traced Codex launch waiting for its rollout, and its `send`;
  - a pane waiting for herdr's report;
  - Kiro's `no_source`;
  - a lookup for a replaced worker writing nothing into the new worker's folder.
- **`bun run smoke:otel`** passed against a local receiver, outside herdr; its pane case was skipped there.
- **Live, on macOS, one Herdr app worker per harness**, with OpenTelemetry export on. Each id was checked against the harness's own files:
  - **Claude Code 2.1.329:** its transcript's name and every line's session id.
  - **Cursor 2026.11.19:** the one chat in the worker's private config folder.
  - **Codex 0.169.0:** its rollout's `session_meta` id. Launch waited until it appeared.
  - **Antigravity 1.5.13:** its transcript's folder name.

  Codex and Cursor were run again after the review fixes. The live runs found two things the fixture tests had not:
  - In a fresh config folder, Cursor's `create-chat` prints its id and then keeps running; its first line is now taken as the answer.
  - Antigravity's prompt history does not record a first message given with `-i`, so routr reads its transcript.
- **Review:** a read-only reviewer on another subscription found four issues:
  - a late lookup could overwrite a replacement worker's record;
  - a reused worker name could match an older session, or two sessions;
  - `create-chat`'s output had no size limit;
  - the `/clear` limit above.

  The first three are fixed, with tests, and the fourth is documented. A second reviewer verified the fixes. Its three small follow-ups are fixed too: a byte-counted limit, a re-check before keeping a found id, and one sentence of the guarantees.
- **Not run live:** a pane worker with this change, Kiro, Windows or Linux terminal workers, and whether the receiver (Myco) joins each span to its session.
