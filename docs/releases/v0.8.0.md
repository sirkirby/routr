## Upgrading from 0.7.0

No configuration change is needed, and none of your settings change: subscriptions, models, effort, reserves,
decision models, `fallback_level`, `sure_at` and update channel are read as before. There are no new settings, so
`routr setup` has nothing new to review.

The update reinstalls routr's skills, and the guides changed in this release: the orchestrator guide has a new
"Outside herdr: headless workers" section. Ask an agent that already loaded routr to reread the skill, or start a new
session. The binary and the guides update together.

**If you run a lead outside herdr:** `routr launch` used to need herdr. It now starts the worker headless instead
(below), so a lead outside herdr that ran `routr launch` and got a refusal now gets a running worker. A lead in herdr
is unchanged: workers still run in panes.

**If a project of yours has a `.env` with `ANTHROPIC_API_KEY`:** routr no longer loads it (below). If `routr usage`
or `routr doctor` showed Claude Code as billed per token in that project, it shows your subscription again.

## Highlights

- **Workers without herdr.** Outside herdr, `routr launch` starts a Claude Code, Codex, Cursor, Antigravity or Kiro
  worker headless, through the harness's own non-interactive mode, on your existing sign-in: no API keys, no new
  accounts. A routr process of its own holds each worker, and four new commands follow it:
  - `routr wait` returns when a worker finishes a turn, with the path of that turn's report, or fails, stops or is
    lost. Name several workers to get whichever finishes first.
  - `routr send` sends a correction or a follow-up. How a correction lands depends on the harness: Claude Code and
    Codex take it into the turn that is running; Cursor, Antigravity and Kiro run it as their next turn, in the order
    sent, after the running one ends (`state: "queued"`). Once a worker is idle, `send` resumes its session, its
    context kept.
  - `routr workers` shows each worker's state, turn, last tool and latest report path, never its text.
  - `routr stop` ends a worker through its own process, and says how many queued messages it dropped.
- **Worktrees outside herdr.** `routr launch --worktree <branch>` makes the worker's git worktree itself, under
  `~/.local/share/routr/worktrees`, as herdr would. `routr cleanup --worker <name>` removes it with the same checks as
  a pane worker's (nothing uncommitted, no file the worker made, no commit no branch holds), then the worker's run
  folder and reports. Outside herdr, `routr cleanup` lists and removes worktrees through git.
- **What it leaves and keeps.** Briefs and messages reach a worker on its standard input only, never in a command
  line or a file. Each turn's report, the worker's own final message, stays in its run folder, owner-only on macOS and
  Linux, until `cleanup --worker`. A Cursor worker runs on a private copy of its config, as in a pane, and Cursor's own
  worker-server, which outlives each turn, is left running and said; it is what any `cursor-agent` run there leaves.
  [docs/guarantees.md](https://github.com/sirkirby/routr/blob/main/docs/guarantees.md), "Headless workers", has the
  full list, including what routr cannot see.
- **routr no longer loads a project's `.env` or `bunfig.toml`.** In a project whose `.env` set `ANTHROPIC_API_KEY`,
  routr's own Claude Code reads (sign-in status, usage) used that key instead of your subscription, so Claude Code
  could read as billed per token, and a decision-model key or `ROUTR_*` variable in that `.env` was used too. Workers
  that `routr launch` starts were not affected.
- **Cursor with herdr 0.9.5.** `routr usage cursor` reads Cursor's usage again (it reported `read_failed`, so routing
  assumed half its headroom), and `routr launch --kind cursor` in a pane starts Cursor again: herdr 0.9.5 answers
  nothing when it types into a pane, and routr took that for no answer.
- **A usage reader that stopped working is said.** When a subscription's last reading is over a day old and its last
  try failed, `routr dispatch` and `routr usage` warn and give the command to read it again, and `routr doctor` lists
  it, instead of quietly ranking on the assumed headroom. A metered seat, which has no reading to make, is not
  flagged.

## Verification

Measured (recorded in [docs/evidence.md](https://github.com/sirkirby/routr/blob/main/docs/evidence.md)), each with the
real harness on a one-file task in a throwaway repository, the outcome read from the commits, each turn's report and
the harness's own session files, not from the worker's account:
- **Claude Code:** launch, report, a follow-up on the same session and cleanup on macOS, Windows ARM64 and Windows
  x64; with `--worktree` on macOS. 1 of 1 each.
- **Codex:** launch, a correction sent mid-turn that changed what it committed, a follow-up that resumed its thread,
  cleanup. macOS, 1 of 1.
- **Antigravity:** launch, corrections sent mid-turn that ran as the next turns, one commit each, a follow-up that
  continued its conversation, cleanup. macOS, 1 of 1.
- **Cursor:** launch, two corrections sent mid-turn that ran as turns 2 and 3 on the same session, a follow-up once
  idle, a stop mid-turn, cleanup with its worker-server still running. macOS: the loop run twice, before and after
  the review's fixes, all turns finished both times.
- **Kiro:** its ACP protocol, measured directly with Kiro itself on macOS. The loop through routr with a real Kiro
  was not run (Kiro was turned off on the measuring machine): watch a Kiro worker's first turn closely.
- **Cursor with herdr 0.9.5:** a live `routr usage cursor` read Included 2% used, class `included`; a pane launch
  started Cursor.

Checked for this release:
- **Reviews:** each change was reviewed by a routr worker on another model family (code) and audited by another
  (docs), then verified again after the fixes.
- **Tests:** `bun test` on macOS, Linux and Windows. Headless workers on Linux, and every harness but Claude Code on
  Windows, ran only against fake harnesses in CI.

Not measured:
- A fresh lead using only the guides, on real work of 30 minutes or more outside herdr.
- A killed holder, a background command left by a worker, and `--worktree` for Codex, Cursor, Antigravity and Kiro.

## CLI and JSON compatibility

**New commands:** `wait`, `send`, `workers` and `stop`, for headless workers; each returns `ok`, `headline`,
`unavailable`, `warnings` and `next` like the others. Their fields are in
[docs/contracts.md](https://github.com/sirkirby/routr/blob/main/docs/contracts.md).

**Changed commands:**
- `routr launch` outside herdr (`HERDR_ENV` not `1`) starts a headless worker instead of failing: `pane` is null and
  `worker` is `{ name, backend: "headless", run, session }`. It needs a task (`--task-file` or `--task`); `--pane` and
  `--direction` are refused there. A `--dry-run` plans the pane launch as before. In herdr nothing changes.
- `routr cleanup --worker <name>` is new, with `--delete-branch` and `--dry-run`. Outside herdr, `cleanup --worktree`,
  `--path` and the list read git instead of herdr, and warn that they cannot see what runs in a worktree's folder.
- `routr dispatch` and `routr usage` add a warning and a `next` step for a usage reader that stopped working;
  `routr doctor` lists it as a step, and `--json` adds `usage_stale` to that harness's entry.

**Removed or renamed:** nothing.

**Config, saved advice, the ledger:** unchanged. Advice saved by 0.7.0 is read by `launch` and `record` as before.

**Telemetry:** unchanged, and off unless you turned it on.
