## Workers are visible in the Herdr app

Herdr's desktop app runs on herdr-core, and its terminals are not herdr panes. So a lead running there used to start its workers headless, with nothing on screen and nothing in the app's Agents list.

Now each worker gets a tab in the lead's space, named for the worker, with its harness's icon and a status mark. It also appears in the Agents list under Working, Done or Needs you, and the app pops up a message when it finishes or fails. A new tab does not take your focus.

The tab runs a new command, `routr watch`. It shows the worker's state, tools, turns and report paths as they change, never the worker's own text. Closing the tab stops nothing, and the tab goes when `routr cleanup --worker` removes the worker.

`routr watch --name <name>` works in any terminal, so you can follow a headless worker outside the app too.

## Upgrading from 0.10.0

No setup is needed, and your settings do not change. The update reinstalls routr's skills, and the guides changed. An agent that already loaded routr reads the older guide until it reads it again or starts a new session.

A lead in a herdr pane works exactly as before, and so does a lead with neither herdr nor herdr-core.

## What this is not yet

This is the first part of supporting the app and herdr-core, not all of it.

- **You see progress, not the harness's screen.** A worker still runs headless, so you cannot type into its tab. Use `routr send`.
- **Setup does not know about the app.** `routr setup`, `routr doctor` and the guides still point you to the older `herdr` and its skill for pane workers. You do not need either for workers in the app.
- **Cursor's usage still needs the older `herdr` installed**, because routr reads it in a private `herdr` session. Without it there is no new reading: Cursor stays offered, and its room becomes unknown once the last reading is too old to use.
- **Remote machines are not supported.** routr never starts a worker on another machine with `hc run --on`.

## How much of this was run

Measured on macOS with hc 0.1.17 and the real app:

- `routr launch` from an app terminal, with Claude Code, Codex and Cursor workers on one small task each. The app listed a named tab per worker, each `working` and then `done`, and the tabs were gone after cleanup.
- How it looks, for all five harnesses, with the real `routr watch` on fixture workers and no model.

Not run: Antigravity or Kiro workers through this path, `routr send` or `routr stop` while watching a tab, a long real task, a core restart or reboot, Linux and Windows in the app. A launch that cannot open a terminal still succeeds, with a warning.

## Known issue: Kiro V3

Kiro CLI 3.0 asks existing users to choose between V3 and V2 on an interactive start, and its notice says V2 will be removed in January. routr does not pass that choice yet, so a Kiro worker in a herdr pane can stop at it. Kiro V3 through routr's headless mode and usage read has not been measured.

## JSON and output changes

These are additions. Nothing was removed or renamed.

- `launch` in a herdr-core terminal: `worker.terminal`, a `terminal` step, and a new warning code, `worker_not_shown`.
- `routr doctor --json`: `core`, with `path` and `inside_terminal`.
- A harness routr starts no longer inherits `HC_TERMINAL_ID`, `HC_TERMINAL_SOCKET` or `HC_SCOPE`. `HC_SESSION` stays.
