## Upgrading from 0.4.1

No configuration migration is required. Your subscriptions, models, effort, account-use preferences, work-level
limits and reserves are preserved, and you stay on stable releases unless you choose otherwise.

One new setting ships: the update channel. To review it, run `routr setup` and pick "Update channel" from the menu,
or set it directly with `routr setup --channel beta` (and `routr setup --channel stable` to go back). Nothing else in
setup changed.

On Windows, if you turned off the background usage refresh because of flashing terminal windows (for example with
`ROUTR_NO_REFRESH=1` or a scheduled task that runs `routr usage cursor`), you can remove that workaround after this
update.

## Highlights

- **No more flashing windows on Windows.** routr's background jobs (the Cursor and Kiro usage refresh, the daily
  updater) opened and closed a terminal window for every program they started: about 20 per Cursor refresh, more
  when Cursor was slow to start. Every program routr starts now has its window hidden, and a test keeps it that way.
  The cleanup helper that removes Cursor's temporary config folder is also started hidden. This was fixed from a
  QA report and checked in CI on Windows; the absence of windows on a Windows 11 desktop is being confirmed by QA on
  this release.
- **Beta update channel.** Choose `routr setup --channel beta` to receive beta and release-candidate builds through
  the normal automatic update (and `routr update`). When a stable release ships that is newer than your beta, you move
  to it. Alpha builds are on no channel. Going back to stable never downgrades by itself: you stay on your beta until a
  stable release passes it, and `routr update --force` switches now. `routr doctor` shows which channel you are on.
- Updates now download the exact version they checked, never GitHub's "latest" link, and ignore malformed or
  mislabelled release tags. Two pre-releases are now ordered correctly (0.5.0-beta.2 after 0.5.0-beta.1).
- When routr reads a harness's usage, sign-in status or model list from inside a herdr pane, it no longer passes on
  herdr's pane variables, so herdr's own integration in that harness does not mistake routr's short read for a
  session in your pane.

## CLI and JSON compatibility

`routr setup` gains `--channel stable|beta`; `routr update` takes no new flag and reads the setting. The config gains
an optional `"update_channel"` (`"stable"` when absent; an unknown value is reported by `routr doctor` and read as
stable). `routr update --json` includes `"channel": "beta"` only on the beta channel, and doctor's automatic-update
status includes `channel`. Telemetry payloads are unchanged.
