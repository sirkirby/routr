## Upgrading from 0.9.5

No configuration change is needed, and no setting is added. The update reinstalls routr's skills, and the orchestrator
and worker guides changed. An agent that already loaded routr reads the older guides until it rereads the skill or
starts a new session.

One input is now refused: `routr launch` refuses a `--model` or `--effort` value containing a quote character (below).
No model id or effort level measured on the five harnesses contains one.

## Changed

- **`routr launch --subagent-model` and `--subagent-effort`.** An opt-in fallback for a worker's subagents that nobody
  names a model or effort for, such as those a skill starts, on Claude Code and Codex. Leave them off unless you have a
  reason for that worker: the worker still decides each spawn, and the lead judges the worker. No test shows that
  smaller subagents keep quality. Cursor, Antigravity and Kiro have no such setting, so launch refuses the flags there.
  - Claude Code takes the fallback as environment variables, set on a pane routr creates and on a headless worker. An
    existing `--pane` gets none, and launch warns. The variables stay in a created pane's shell until `routr cleanup`
    closes it.
  - Codex takes it as config overrides on its command line.
  - A headless worker keeps the fallback in its settings in the run folder, so a later `send` that restarts it applies
    them again.
- **Same worker or a fresh one.** The orchestrator guide gives a rule of thumb: related work goes back to the same
  worker, and unrelated work goes to a fresh one, even when one is idle. The lead makes the call.

## Fixed

- **Quote characters in launch values.** `--model`, `--effort` and the two new flags refuse ASCII quotes and U+2018 to
  U+201E, on every shell, before anything starts. PowerShell treats those as quotes, and a value holding one could break
  the command a pane runs.
- **Windows cmd prompts.** Launch now recognises a prompt shaped like `user@host C:\path>`. It timed out on that prompt
  before starting the agent.

## Compatibility

`launch` output gains two warning codes when the new flags are used: `subagent_effort_version` and
`subagent_fallback_not_passed`. OpenTelemetry export can send them, as it does other warning codes, and
`docs/opentelemetry.md` lists them. The fallback values appear in `start` and in a dry run's `would_run`. They are not
added to the ledger or telemetry. Nothing changes when the flags are not given, apart from the refusal above.

## Verification

- `bun test`: 784 pass, 7 skip, 0 fail; all three platform jobs green.
- Setting both model and effort on the spawn beat a differing fallback on Claude Code 2.1.316 and Codex 0.166.0, one run
  each, read from the child's own record. One setting alone was not measured.
- Windows 11, PowerShell and cmd: real panes delivered the Codex arguments byte for byte to a fixture `codex.exe`, and
  Codex 0.166.0 on macOS read those values correctly. Codex itself was not run on Windows.
- Windows 11, Claude Code 2.1.308: the variables reached a real worker's shell. Anthropic's changelog lists the effort
  variable from 2.1.316, so whether effort applies on that version was not tested.
- `smoke:carriers` passed in live herdr and `smoke:otel` passed. An independent review and docs audit found three code
  issues and four documentation issues: five were fixed, two were settled as documented behaviour, and a verification
  pass confirmed the result.
- The same-or-fresh rule rests on a study of 615 follow-ups (`docs/evidence.md`). The first Claude Code request after
  its prompt cache expired cost about 25 times a live one, and a fresh start-up was estimated at about the same as that
  request, so expiry alone does not favour starting fresh. The rule about unrelated work follows from how context is
  charged and was not measured, and quality was not compared.
