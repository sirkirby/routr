## `routr dash`: your ledger over weeks, in one page

`routr dash` writes one HTML page of this machine's ledger and, at a terminal, opens it in your browser. Where `routr top` shows the last 7 days as they happen, dash shows the long view: what you asked routr, what you chose, and how it turned out.

- **Tiles:** recorded runs, how often the chosen level was the advised one, done first time, the share on your two most-used accounts, failed checks.
- **Charts and tables:** chosen level against advised level per week; runs per account per week; each account's usable room in the advice beside the share of work it got; the level, account, model and effort chosen, as you recorded them; done first time per week; the causes of extra work; and how often routr was torn or called work high risk, by project. Each chart has a table beside it.
- **Filters:** project, preselected from the folder you run it in, and period: 30 days, 90 days or all time.

It counts and does not judge: no cost, no score, no recommendation. It is for the machine it runs on, from that machine's ledger. It calls no harness and makes no network call, and the page loads nothing.

The file is `~/.cache/routr/dash.html` unless you name another with `--out`. Piped, or with `--no-open`, it opens nothing and gives the path, so an agent can hand it to you.

## Safer with what it writes

- **A symlink is replaced, not followed.** The page is written to a temporary file and renamed over the path.
- **`--out` will not overwrite your files.** It writes a missing file or a page dash wrote earlier, and refuses anything else, naming the path.
- **The page holds no note, brief, path or id.** Each run is projected field by field.

## A ledger value that is not what it should be is left out

A value in `advised` or `chose` that is not a level, a short string, a boolean or a number is now left out of `routr board`, `routr top` and `routr dash`, and `routr record` no longer stores one from an advice file. Before, a malformed or hand-edited value, such as an object in place of a model name, was copied whole into `board`'s output. Good rows are unchanged, and a chosen model is stored exactly as recorded.

## Upgrading from 0.13.0

No setup is needed, and your settings do not change. The update reinstalls routr's skills; the setup guide and README mention `routr dash` in one line each.

## How much of this was run

Measured on macOS:

- **The page on a real ledger:** built from source on the maintainer's ledger (521 runs) with `--no-open` and drawn in a headless browser, with no console errors. A prototype of the same page was drawn at 1100 and 390 pixels wide, light and dark, and looked at by the maintainer.
- **A compiled build outside a checkout,** with a temporary home, wrote the page from the copy embedded in the binary and nothing else.
- **The file rules:** a symlink at the default path was replaced and its target left unchanged; `--out` refused an existing file that was not a dash page and left it as it was.
- **The ledger values:** a ledger row and an advice file with objects and arrays in every advised and chosen field put nothing of them into `board`, `top` or `dash`, in the tests and in a reviewer's own runs.

Not run: opening a browser on Linux or Windows (the commands are tested, not started), the page on Windows, and how dash affects anyone's choices.

## JSON and output changes

- New command: `dash`, with `ok`, `headline`, `unavailable`, `warnings`, `next`, `file`, `opened`, `runs` and `project`.
- `board`: an `advised` or `chose` field holding anything but a level, a short string, a boolean or a number is now null. Good rows are unchanged.
- `record`: an advice file's level, `between`, work type, booleans and fact probabilities are stored only when they have their documented type; otherwise null.
