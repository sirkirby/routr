## Terminal workers in the Herdr app: `routr wait`, `routr send` and `routr stop`

In the Herdr app, a worker that `routr launch` starts in a tab of its own is now followed by the same commands as a headless worker:

- **`routr wait --name <name>`** asks hc for the worker's status and returns when its turn ends, when it needs input, or when its terminal ends. A turn has no report file, so `next` says to read it with `hc read <t> --lines 200`. No terminal text reaches routr's output. Before its first turn, while the worker is idle at turn 0 (right after you answer a startup question, for example), it is `starting`: wait keeps waiting, and a timeout says it has not started its task yet.
- **`routr send --name <name>`** writes your message to an owner-only file in the worker's run folder and types only a pointer to that file. The message never appears in `ps`. **It never types into a harness at a question**, or into one that has reported no status yet. Typed at Claude Code's folder question, hc's Enter picks "No, exit" and the worker ends, as was seen live. In that case send refuses with "nothing was sent" and gives the steps to read and answer the question first.
- **`routr stop --name <name>`** ends the terminal with `hc kill`, after checking that the terminal carries the worker's id.

Steps in `launch`, `workers` and `cleanup` now point at these commands. `hc read` stays the way to read a report or a question. Cursor reports no status, so `routr wait` still says to follow a Cursor worker with hc. `send` and `stop` work for it.

## Usage readings are kept in a new place

routr now keeps each subscription's usage reading in its own file under `~/.cache/routr/usage/`. **After upgrading, Cursor and Kiro read "no reading yet" until their first background refresh lands.** A command that reads usage, such as `dispatch`, `usage`, `board` or `top`, starts that refresh, and `routr usage cursor` or `routr usage kiro` takes a reading at once. Readings from earlier versions are not carried over. Claude Code, Codex and Antigravity are read live as before.

The old files (`cursor-usage.json`, `kiro-usage.json`, `usage-readings.json`, `usage-refresh.json` in `~/.cache/routr`) are removed only when no older routr can still be using them: a file goes once it has been unchanged for a day and its lock is absent or stale.

Two fixes come with this:

- A background refresh of Cursor's or Kiro's usage now reads the subscriptions of the `--config` its caller was given. It used to read the default config.
- `routr board` no longer repeats "a fresh reading is being taken in the background" long after that was true. It says so only when that call started one.

## `routr cleanup --worker` follows the worker, not the name

`cleanup --worker` now checks, under its lock, that the worker is still the one it found. If a worker was launched again under the same name while cleanup waited, cleanup keeps the new worker and says its record changed. Before, it finished the new worker. `send`, `stop` and `watch` make the same check at the moment they act.

## One launch id again, with OpenTelemetry export on

With OpenTelemetry export on, a launch from the command line carried two ids. The trace and the worker's record had one, and the launch's answer and record template had another. So `routr record --launch <launch_id>` linked no span. A launch now has one id in its answer, its trace and its worker's record. With export off, nothing changes.

## Smaller changes

- **`routr top` and `routr dash` outside a git repository** show the folder's project, which is the name launch and record give it, instead of every project. Only a filesystem root, which has no name, still shows every project. In a repository nothing changes.
- **The `routr dash` page counts "done first time" out of every recorded run**, as `routr assess` and `routr board` do. Before, the page left out runs that recorded no attempts, so its rate could read higher. Mean attempts still uses only the runs that recorded them, and the page says how many did not.
- **`routr usage --help`** says Cursor's usage read needs herdr installed on Windows only. On macOS and Linux it reads in a terminal of routr's own, as it has since 0.12.0.
- **`routr doctor`**: a usage reader that stopped working now ends with "Try reading <subscription>'s usage again: routr usage <subscription>", in the same words as `dispatch` and `usage`.
- **`routr watch` in a herdr pane** no longer sends the Herdr app's status codes or a terminal title when that pane's session was started from an app terminal.
- **`routr constructor`, `routr toString`** and other names every JavaScript object has are now unknown commands: they print the usage and exit 2. Before, they exited 0 with no output.
- **A command line routr refuses as unknown usage**, such as `routr --config <path> launch`, no longer records an OpenTelemetry span for a command that never ran.

Most of this release's work is internal. Each concept routr has (a worker, a harness, a launch's identity, the usage readings, the command table, the capacity view, a worker's environment) now lives in one module, with tests that check its behaviour through the module's interface. `GLOSSARY.md` names these concepts.

## Upgrading from 0.13

No setup is needed, and your settings do not change. Expect Cursor and Kiro to read "no reading yet" until their first refresh, as described above.

The update reinstalls routr's skills. The orchestrator guide's section on the Herdr app now says to wait, send and stop with routr. An agent that already loaded routr reads the older guide until it reads it again or starts a new session.

## JSON and output changes

- `wait`: a terminal worker's row now has `state` `working`, `starting`, `idle`, `failed`, `stopped`, `lost` or `unreachable`, plus `status` (hc's), `turn` and `turns`, like a headless worker. Before, `wait` did not wait on a terminal worker: it gave a `terminal_followed` warning saying to follow it with hc. It still does so for Cursor.
- `send` and `stop`: a terminal worker is acted on. Before, both answered `state: "refused"` for one. A send that types nothing still says "nothing was sent".
- `cleanup --worker`: a worker launched again under the same name while cleanup waited is kept, and the answer says its record changed.
- `dash`: `project` is the folder's name outside a repository, and null only at a filesystem root. Before, it was null outside any repository.
- `doctor`: `usage_stale` ends "Try reading <subscription>'s usage again: routr usage <subscription>". Before, it ended "Try it again: routr usage <subscription>".
- OpenTelemetry: a command-line launch's `routr.launch.id` is its `launch_id`.

## How much of this was run

Measured on macOS:

- **Terminal workers, live in the Herdr app** with real Claude Code workers: launch, `wait` through a first and a second turn, `send` (the worker read the file it pointed to and answered), `stop` and `cleanup --worker`. `send` refused, with nothing typed, while a worker sat at its folder question. A `send` followed at once by `wait` waited through a 15-second turn. The `starting` state at turn 0 is covered by tests only.
- **`cleanup --worker` and the other worker commands**, live with a real headless Claude Code worker: launch, wait, workers, send (it resumed its session), wait, stop and cleanup, with the same answers as 0.13.
- **Usage reads:** `bun run smoke:usage` read Claude Code, Codex, Cursor and Antigravity live. A real `routr usage` claimed Cursor, its detached refresh wrote a fresh reading to the new store, and the old files were removed. Kiro is turned off on this machine and was not read.
- **Worker environment:** `bun run smoke:carriers` passed inside a live herdr session.
- **`routr dash`:** a page written from a test ledger, opened in a browser. Its tests now run the page's own script.

Not run: terminal workers on Windows or Linux (the tests drive them on all three systems with a fake hc), a Kiro usage read, and the old-file cleanup on a machine where an older routr is still running.
