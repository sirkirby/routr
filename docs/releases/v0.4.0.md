## Upgrading from 0.3.x

**You do not need to rerun full setup.** Existing configurations remain valid. The updater preserves your account preferences and reinstalls the bundled agent skill. If an agent has already loaded the old guide, ask it to reread the installed routr skill and its orchestration guide, or start a new session.

**Review Account use once if you want funded enterprise or other usage-based accounts considered for everyday work.** Run `routr setup`, choose **Change one subscription's settings**, choose the account, then **Account use** → **Normal use**, and save. Or set the accounts you want directly:

```sh
routr setup --yes --use claude=normal --use codex=normal
routr usage
```

Use the names of your installed, signed-in accounts. `routr usage` shows `candidates.normal` and `candidates.fallback`. Normal use permits everyday consideration; the lead still chooses a suitable model and effort, and disabled, signed-out or exhausted accounts remain unavailable.

Without an explicit `use`, metered accounts with legacy `metered_rank: "after"` (the default) stay fallback; `"with"` means normal. Other accounts default to normal. Running `routr setup --yes` alone preserves existing preferences; use `--use` to change them. No `--force` is needed.

Normal use does not set or enforce a spending budget. Routr cannot infer shared prepaid balances or personal allowances. Metered `headroom` and `usable` are now always `null`, including legacy `metered_rank: "with"`; `most_room` is `null` when only metered candidates remain. Consumers of the JSON output should use candidate groups for eligibility and treat `ranked` / `most_room` as capacity diagnostics.

## Highlights

- Choose normal or fallback account use independently of billing. The lead considers model/effort suitability before comparing capacity; funded usage-based accounts can be normal candidates.
- Record optional outcome causes and revise a specific run with `--run-id`. Local assessment separates verified acceptance, execution corrections, review follow-ups and launch trouble. Attempts alone do not rate models; older records with missing evidence remain unknown.
- New run IDs and causes stay local; the telemetry projection is unchanged. Comparative quality, cost and completion-time improvements have not yet been measured.
