## Read this first: a metered seat with no `use` set now gets everyday work

**routr updates itself, so this can reach you without you doing anything.** A metered account is one billed per use, such as an Enterprise seat. Until now, a metered account with no `use` set counted as `fallback`: routr offered it only when no other account fit. It now counts as `normal` and is offered for everyday work, which spends money.

You are told only if your config still has an old `metered_rank` for that account. A metered account with no `use` and no old key, such as one you marked `billing: "metered"` by hand, moves to everyday work with no warning.

To keep an account out of everyday work:

```sh
routr setup --use <name>=fallback
```

To check every account, run `routr doctor`. Each account's line ends in `normal use` or `fallback use`.

An account with `use` already set does not change. Neither does an included plan with no `use` set: it was `normal` already.

## Upgrading from 0.9.6

Beyond the check above, no setup is required. The update reinstalls routr's skills, and the guides changed. An agent that already loaded routr reads the older guides until it rereads the skill or starts a new session.

Your settings are kept, including `hardest_work`, `reserve`, `share`, `use` and `billing`.

- **Removed settings.** `metered_rank` and `assumed_headroom` no longer do anything. If your config has either, routr warns on each call that reads it. The next `routr setup` change removes them, or delete them by hand. Reading your config never rewrites it.
- **Removed flag.** `routr setup --metered` is gone. Use `--use <name>=fallback` or `normal`.
- **Unknown setup flags are refused.** `routr setup` used to ignore a flag it did not know. It now stops and changes nothing, so an old script fails plainly.

## Changed

- **Use is only your choice.** If unset it means `normal`, and it never changes because of what routr reads.
- **A simpler account model.** A class now says how an account is paid for: `included` or `metered`, or `unknown` when it cannot be told. A budget an owner sets in an admin console is one more usage window on a metered account, not a kind of its own.
- **No invented room.** An account whose usage cannot be read used to be ranked on an assumed 50%. Its room is now unknown: it stays offered, with a note saying why, and `unavailable` lists the failed read.
- **`most_room` names a normal account** when one has a number. It could name a fallback account before. The candidate lists were already right.
- **`routr wait --timeout` no longer refuses a wait over 10 minutes**, so a wait running in the background can last as long as the work. That is also how long you may go without hearing about a worker that hangs. A worker that dies is still reported.
- **Shorter docs.** The account parts of the ranking page are about half the length.

## Fixed

- **Your launch ratio with a budget.** A metered account with a limit used to drop out of the `share` ratio silently, which could end the ratio. It now stays in while it has room, and leaves at its limit.
- **Codex member limits.** The note saying a seat "keeps working past 100%" no longer appears beside a member limit, where it was false. A reset one second past the month boundary no longer stops the reserve from tapering. A reached spend control means no room. If no reset comes with it, it is trusted for 5 minutes, so an old session log cannot block a seat forever.
- **A usage skill of your own no longer spends through routr.** A skill folder or command named `usage` in your Claude config replaces Claude's own `/usage`, and routr's read then made a real model call each time. routr now checks for those two names first, and if one exists, it does not read and says why. An answer that used a model turn is not treated as a reading, but that turn has already been spent.

## What routr does not do

routr does not see a Claude Enterprise budget. It appears only on Claude's interactive screen, and routr does not read that. Anthropic enforces the budget, so a worker on an exhausted seat fails and the lead moves the work. A limit that routr reads from Codex is the owner's own, set in the admin console. routr has no spend limit of its own.

## Compatibility

JSON output changes:

- `class` no longer has the value `capped`. A Codex seat with a member limit reads `metered` and carries a `monthly_cap` window, with a number in `usable`.
- `usage` on a ranked row no longer has the value `assumed`. Without a number it is `metered` or `unknown`.
- `reading` in an `unavailable` entry says `unknown` where it said `assumed`.
- A new failure code, `command_shadowed`.
- The `dispatch` and `usage` headline and note wording changed: they now say "(normal first)" and "Remaining capacity is unknown". Do not parse them.

OpenTelemetry's `routr.usage.state` sends `unknown` where it sent `assumed`, and `command_shadowed` can appear as an error code. `docs/opentelemetry.md` lists both. Telemetry is unchanged: it sends no account class or usage state.

## Verification

Measured on macOS, 2026-11-03, with no model call unless stated:

- Codex 0.166.0 on an Enterprise seat: 71% left under a limit, and `remainingPercent: 0` with `spendControlReached: true` at one. Those replies are test fixtures.
- Claude Code 2.1.317 with a project skill at `.claude/skills/usage`: `claude -p /usage` made one model turn, reported at $0.1257. A skill in another folder with `name: usage` did not take over. routr's check looks at the user-level locations, which were not measured directly, and a plugin or managed skill was not measured.
- A binary built with the release flags, on two Enterprise sandbox seats with `share` 2 and 1, from a folder holding its own `.env`: an account with no `use` and an old `metered_rank` read as normal with one warning, and `share_due` named Claude at a target of 67%.
- An old config, by hand: `--metered` was refused with the config unchanged, and the next setting change removed both old keys.
- New tests check routr against the setups people run, such as personal plans at reserve 0 and two metered seats at a 2:1 ratio. Six of the twelve fail on 0.9.6's code.
- `bun test` and all three platform jobs green. `smoke:usage` on default logins and `smoke:otel` passed. Independent reviews and verification passes were run on each of the three changes.

Not checked: a model request at a limit, a close-to-limit read, a spend control with no member limit and a fresh limit reading with a past reset (both from made-up inputs, not seen live), and Linux or Windows beyond CI. Whether the new default spends more for anyone was not measured.
