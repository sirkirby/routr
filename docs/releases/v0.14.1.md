## `routr wait` says when a terminal worker is at a question

In the Herdr app, `routr wait` now returns a terminal worker that is waiting at a question, with state `needs_input`. The headline says `<name> needs input`. `next` gives three steps: read its terminal with `hc read`, answer with `hc keys`, and wait again. Before its first turn, the answer follows the same rule as at launch: accept folder trust only for a folder you created, or a worktree of the repository you are working in, and ask the user for anything else.

A worker counts as at a question when:

- hc reports it `blocked`, or
- its harness has reported no status at all for 20 seconds since routr started it. Launch already uses the same 20-second rule, though it counts from its own first look at the terminal. Claude Code's folder question is one example: it comes before Claude Code reports anything.

In 0.14.0, a worker at Claude Code's folder question was taken as not yet started. `wait` held out to its timeout and said only to wait again. A worker hc reported `blocked` came back as `idle`, with no steps.

Each question is news once. A later wait on that worker alone, while it still sits at the same question, returns at once, saying again that it needs input, with the same steps. A wait that also watches a worker still running waits for that one, and then says the question again. A question at a later turn is news again.

## `routr wait` never calls a failed turn finished

A turn that did not finish is now headlined by how it ended, such as `<name>'s turn 1 failed`, `was stopped`, `ended without finishing` or `did not start`, never "finished a turn". In 0.14.0, a wait that caught a failed turn before the worker settled headlined it as finished. Only the turn's `outcome` field said `failed`. This was seen with Claude Code turns that failed to sign in.

## Help text

- `routr top --help` and `routr dash --help` now say what 0.14.0 does: a folder outside a git repository is its own project, and only a filesystem root shows every project.
- `routr send --help` says the message file is owner-only on macOS and Linux. On Windows it takes your home folder's permissions.

## Upgrading from 0.14.0

No setup is needed, and your settings do not change. The update reinstalls routr's skills. The orchestrator guide's "In the Herdr app" section now describes `needs_input` from `routr wait`. An agent that already loaded routr reads the older guide until it reads it again or starts a new session.

## JSON and output changes

- `wait`: a terminal worker's row can have `state: "needs_input"`, with `why` saying what routr saw: hc reported it blocked, or it has reported no status for 20 seconds. Like `failed` or `lost`, it is reported as news once (once for each turn a question comes at), so the command's `state` is `finished` that first time. Later waits that watch nothing still running answer `idle`, headlined `<name> needs input`. A `blocked` worker was `idle` before.
- `wait`: the headline names each turn that did not finish by its outcome (`<name>'s turn 1 failed`; `<name> finished a turn, turn 2 failed`), and adds `and needs input` when a turn ends at a question. The `turns` field is unchanged.

## How much of this was run

- **The question, live on macOS** with a real Claude Code worker in the Herdr app, sent into a folder Claude Code had never seen:
  - `launch` and `wait` both said it needed input, and `wait` returned at once with the steps. A second wait said the same.
  - After the question was answered, the next wait reported the finished turn, and cleanup ran.
- **The published 0.14.0, live:**
  - **macOS:** headless, terminal and pane workers through launch, wait, send, stop and cleanup.
  - **Windows 11:** a headless worker through the same steps.
  - **Linux:** the same steps, until the worker's Claude Code sign-in expired. That is where the failed-turn headline was found.
- **Not run live:** a worker hc reports `blocked` partway through a task, the new failed-turn headline (routr's own sign-in check stops a launch that would reproduce it), and terminal workers on Windows or Linux. The tests cover each of these.
