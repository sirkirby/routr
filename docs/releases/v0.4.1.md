## Upgrading from 0.4.0

No configuration migration or setup change is required. Your everyday models, effort, account-use preferences,
work-level limits and reserves are preserved. You can run `routr setup` to review those choices; it keeps existing
settings unless you change them.

The update reinstalls the bundled agent skill. Ask an agent that already loaded routr to reread the installed skill
and orchestrator guide, or start a new session, so it uses the revised decision procedure.

## Highlights

- The lead chooses model and effort for a verified, high-quality result, then compares efficiency and capacity
  among suitable options. Everyday defaults are preferences, not assignments to difficulty levels. The lead
  explains its choice and can change model or harness when verified results warrant it.
- When the lead changes the advised difficulty, `routr usage --level basic|standard|strong` refreshes eligible
  accounts without reassessing the brief. It keeps the original advice for launch and recording, and respects
  existing account limits, sign-in requirements and reserves.
- Recording guidance distinguishes task difficulty from model choice, separates execution corrections from brief
  gaps and other causes, and leaves unobserved attempt counts and timing unset.
- Invalid level arguments are rejected before named usage refreshes, including when malformed global options
  appear before the command or would consume a level flag.

## CLI and JSON compatibility

Plain `routr usage` retains its existing basic-work view and JSON shape. The new unnamed `usage --level` form adds
a top-level `level` field identifying the filter used, alongside existing candidates and capacity diagnostics.
For example:

```sh
routr usage --level standard
```

Use one space-separated `--level` value. Combining it with a subscription name or `--background`, repeating it,
or supplying an invalid value returns an explanatory JSON error with exit status 0. Existing valid named usage
commands keep their behavior. The original dispatch assessment and the recorded chosen level remain separate.

Setup has no new required choices, and telemetry payloads are unchanged. The revised guidance has been checked
with synthetic decisions, independent code review, tests and CLI smokes; improved quality, completion time or
spend on real coding tasks has not yet been established.
