This is a pre-release for the beta update channel (`routr setup --channel beta`). Stable users are not offered it.

## Upgrading from 0.4.2

No configuration migration is required, and setup has no new choices. If you already use `routr statusline` as
Claude Code's statusline, nothing changes for you: routr keeps using its reading while it is under five minutes old,
and your statusline keeps working. `routr uninstall` still removes routr's statusline entry.

If you have your own statusline, or none, routr now reads Claude Code's usage anyway. You no longer need to change
your statusline for routr. `routr doctor` shows where Claude's reading came from (`claude /usage` or `statusline`).

## Highlights

- **Claude Code's usage is read from Claude itself.** routr runs `claude -p /usage`, which Claude answers locally
  (no model turn, no tokens), instead of depending on owning Claude's statusline. Before, anyone with their own
  statusline silently got an assumed 50% headroom. Measured on Claude Code 2.1.289 (macOS): about 3 to 5 seconds,
  read alongside routr's other usage reads.
- **Your Claude setup is left alone.** For routr's own read, your hooks and MCP servers are switched off for that one
  run (`--settings {"disableAllHooks":true}` and `--strict-mcp-config`); your other Claude settings still apply.
  Nothing in your Claude configuration is changed. Each read runs from its own temporary folder, and routr removes the
  empty project folder Claude makes for it; a read that times out can leave one empty folder under
  `~/.claude/projects`.
- **Setup no longer installs the statusline**, and doctor no longer asks for it. `--no-statusline` is still accepted
  and does nothing.
- **`routr launch` and a worker's startup question.** After you answer a worker's startup question (Codex's folder
  trust, for example), running launch's `then` command right away now hands the worker its task when herdr already
  reads it ready, instead of reporting it as still waiting. launch never waits on, or sends a second task to, a
  worker it did not start that is busy.

## Not yet verified

Windows: a natively installed `claude.exe` is started the same way as every harness; an npm-installed `claude.cmd`
cannot be started without a shell (a known limitation for every harness, to be addressed). Linux, and Claude Team,
Enterprise and API-key seats (what `/usage` shows there has not been observed). Reports from beta users on these are
welcome (`routr feedback "<text>"`).

## CLI and JSON compatibility

A usage row for Claude can now have `"source": "claude /usage"` as well as `"statusline"`. Its windows keep the same
names (`five_hour`, `seven_day`). `routr launch` `needs_input` may carry `herdr.explained` (herdr's live reading) and
then omits `rule`. Telemetry payloads are unchanged.
