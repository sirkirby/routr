## Upgrading from 0.5.0

No configuration migration is required, and setup has no new choices. The update reinstalls both skills. Ask an
agent that already loaded routr to reread the skill, or start a new session, so it uses `routr cleanup`.

If earlier orchestrations left worktrees behind, `routr cleanup --cwd <repo>` lists every worktree of the repository
and whether it can be removed safely; `routr cleanup --cwd <repo> --path <path>` removes one and keeps its branch.

## Highlights

- **Workers are finished with `routr cleanup`.** The guide used to say to close a worker's pane and later run
  `herdr worktree remove`. That cannot work: a worker's worktree pane is its workspace's only pane, closing it closes
  the workspace, and herdr then cannot find the worktree (measured on herdr 0.9.3). Worktrees piled up; one
  repository held 25. `routr cleanup --cwd <repo> --worktree <branch>` removes the worktree and closes its workspace in
  one call, and `routr cleanup --pane <id>` closes a worker launched without a worktree. Every `routr launch` result
  now carries the exact `cleanup` command for that worker.
- **Cleanup never takes work with it.** It refuses while an agent is working or waiting at a question, while a command
  runs in a pane, or when it cannot tell; and it refuses a worktree with uncommitted changes, files the worker made,
  files git is told not to check, or a commit no branch or tag holds. It never forces a removal, and it reads the
  commit and the panes again right before removing. Files copied in with `launch --copy` and left unchanged go with
  the worktree, and so do files git ignores, as with `git worktree remove`. The branch is kept unless you pass
  `--delete-branch`, and then deleted only if git agrees it is merged. Neither herdr nor git can remove a worktree
  only if it is unchanged, so a worker started in the moment after the last check is not ruled out.
- **`routr launch --base <ref>`** starts a worker's branch at another branch, tag or commit: stacked work, or a reviewer
  of one commit, no longer needs a worktree made by hand.
- **Both skills and the orchestrator guide** now say the same thing: start every worker with `routr launch`, finish it
  with `routr cleanup`.

## Verification

An independent worker on another harness reviewed `cleanup` adversarially over three passes (13 findings: races,
links swapped in for folders, reads that failed open, a missing test), each reproduced with real git or a mutation
and fixed; every guard has a test that fails without it. A second worker audited the guides against the code. End to
end runs against a private herdr session on macOS covered each case, and `cleanup` then removed 25 left-behind
worktrees from a real repository, keeping every branch. Linux and Windows ran the test suite in CI; `cleanup` against
a live herdr session there is not yet observed. Reports are welcome: `routr feedback "<text>"`.

## CLI and JSON compatibility

New command `routr cleanup` (JSON: `ok`, `state` of `removed`, `closed`, `listed`, `planned`, `absent`, `refused` or
`failed`, with `refused.why` and `refused.then`; exit 1 unless `ok`). `routr launch` takes `--base` (with
`--worktree`), and its result adds `cleanup` and, with `--base`, `worktree.base`. Telemetry payloads are unchanged.
