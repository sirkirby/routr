## `routr dash`: your ledger over weeks, in one page

`routr dash` writes one HTML page of this machine's ledger and, at a terminal, opens it in your browser. Where `routr top` keeps the newest decisions and 7-day counts current, dash shows the long view: what you asked routr, what you chose, and how it turned out, week by week.

- **Tiles:** recorded runs, how often the chosen level was the advised one, done first time, the share on your two most-used accounts, failed checks.
- **Charts and tables:** chosen level against advised level per week; runs per account per week; each account's usable room in the advice beside the share of work it got; the 12 level, account, model and effort combinations you chose most, with the rest counted together; done first time per week; the causes of extra work; and how often routr was torn or called work high risk, for your 8 busiest projects. Each chart has a table beside it.
- **Filters:** project, preselected from the folder you run it in (`--cwd <folder>` names another; the file holds every project either way), and period: 30 days, 90 days or all time.

It counts and does not judge: no cost, no score, no recommendation. It is for the machine it runs on, from that machine's ledger. It calls no harness and makes no network call, and the page loads nothing.

The file is `~/.cache/routr/dash.html` unless you name another with `--out`. Piped, or with `--no-open`, it opens nothing and gives the path, so an agent can hand it to you.

## Safer with what it writes

- **A symlink is replaced, not followed.** The page is written to a temporary file and renamed over the path.
- **`--out` will not overwrite your files.** It writes a missing file or a page dash wrote earlier, and refuses anything else, naming the path.
- **The page holds no note, brief, path or id.** Each run is projected field by field.

## A ledger value that is not what it should be is left out

A field in `advised` or `chose` that does not have its documented type (a level, a string, a boolean or a number; `between` a list of levels) is now null in `routr board`, and is not drawn by `routr top` or `routr dash`, where a torn or high-risk reading that is not `true` counts as not torn and not high risk. `routr record` no longer stores such a value from an advice file. Before, a malformed or hand-edited value, such as an object in place of a model name, was copied whole into `board`'s output. A fact whose name or probability is not valid is left out. These three commands also cut a long string for display: a work type at 32 characters, an account, model or effort at 128. The ledger keeps a chosen model exactly as recorded.

## Upgrading from 0.13.0

No setup is needed, and your settings do not change. The update reinstalls routr's skills; the setup guide and README mention `routr dash` in one line each.

## How much of this was run

Measured on macOS:

- **The page on a real ledger:** built from source on the maintainer's ledger (521 runs) with `--no-open` and drawn in a headless browser, with no console errors. A prototype of the same page was drawn at 1100 and 390 pixels wide, light and dark, and looked at by the maintainer.
- **A compiled build outside a checkout,** with a temporary home, wrote the page from the copy embedded in the binary and nothing else.
- **The file rules:** a symlink at the default path was replaced and its target left unchanged; `--out` refused an existing file that was not a dash page and left it as it was.
- **The ledger values:** a ledger row and an advice file with objects and arrays in every advised and chosen field put nothing of them into `board`, `top` or `dash`, in the tests and in a reviewer's own runs.

Not run: opening a browser on Linux or Windows (the commands are tested, not started), the page on Windows, and how dash affects anyone's choices.

## JSON and output changes

- New command: `dash [--cwd <folder>] [--out <file>] [--no-open]`, answering `ok`, `headline`, `unavailable`, `warnings`, `next`, `file`, `opened`, `runs` and `project`. A refusal (a missing, repeated or invalid value, an unknown argument, an `--out` file that is not a dash page, a failed write) is `ok: false` with `error` and none of the last four fields, and exits 0, as board's does. An unreadable ledger is `ok: true` with `runs: null` and a `ledger` entry in `unavailable`. A browser that does not open is `ok: true`, `opened: false`, with the path in `next`. A `--config` is accepted and not read; a given `--headroom` is not used and is warned about.
- `board`: an `advised` or `chose` field without its documented type is now null; a fact with an invalid name or probability is left out; long strings are cut as above.
- `record`: an advice file's level, `between`, work type, `sure` and `high_risk` are stored only when they have their documented type, otherwise null; its facts only with a valid name and probability. `fallback` is worked out from the advice as before.
