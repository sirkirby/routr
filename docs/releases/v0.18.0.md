## Choose OpenAI's GPT-6 Luna as your decision model

routr can now ask OpenAI's GPT-6 Luna the same fixed questions it asks Jev and Clef, through OpenAI's Decisions API. It is opt-in: Jev stays the default, and nothing changes unless you choose it. Thanks to @TeknoCentral, who wrote the provider (#187).

To use it, you need an OpenAI API key from https://platform.openai.com/api-keys. Each request is metered on your OpenAI account. Then:

    routr key set openai                       # asks for the key without showing it, saves it readable only by you, tests it
    routr setup --yes --decision typesafe,openai   # Jev first, GPT-6 Luna as its backup; or openai alone, or openai first

At a terminal, `routr setup`'s "Decision model" menu offers it too. `routr doctor` tests each decision model in your list and says whether it answers.

## How it reads, from the model gate

The maintainers' gate ran it three times beside Jev 1.14.0 on the same saved items, on 2026-11-20. Full results are in [the evidence](../evidence.md#openais-gpt-6-luna-2026-11-20).

- **Levels:** 85 of the 104 labelled briefs right, against Jev's 82.7. But it reads more of them one level too low: 11 against 8.3. On the 36 real tasks it gets 26 right, against Jev's 28.3. Too low is the costlier mistake.
- **"Standalone":** it is decisively wrong that a brief needs no more context on 8 of 78 briefs, against Jev's 2.
- **Facts and reports:** all 12 yes/no facts are more often decisive than Jev's, and it was right on all 23 expected readings of the report checks. It gave identical answers on every repeat.
- **Refusals:** OpenAI's API can refuse a single question. GPT-6 Luna refused one yes/no question on 3 of 129 briefs, and did so every time those briefs were asked again. routr then drops that reply and asks the next decision model in your list. With no next model, it uses your fallback level. So give it a backup.
- **Pin:** OpenAI offers only the name `gpt-6-luna`, with no dated version, so the model behind it can change. The gate is re-run on it, as for Clef. `routr doctor` notes this beside it.

As a replacement for Jev, it fails the gate: it reads more levels too low and does worse on the real tasks. It is offered beside Jev, as Clef is.

## Keep `OPENAI_API_KEY` out of your shell

routr also reads `OPENAI_API_KEY` from your environment, and a value there wins over the saved key. But every harness routr starts from that shell inherits it too, Codex included. Codex 0.169 still reported its ChatGPT sign-in with the variable set, but whether it changes what Codex bills is not measured. Save the key with `routr key set openai` and leave the variable unset.

## Upgrading from 0.17.0

No setup is needed, and your settings do not change. Your decision list stays as it is until you add `openai` to it.

The update reinstalls routr's skills; the setup guide now describes GPT-6 Luna. An agent that already loaded routr reads the older guide until it reads it again or starts a new session.

## JSON and output changes

- A new decision failure code, `declined`: the model refused a question. Like `timeout` or `provider_error`, it moves on to the next decision model, and it appears in `unavailable` with its recovery action.
- `openai` is a new decision `provider`, in advice, the ledger, telemetry (when you turned it on) and OpenTelemetry's `gen_ai.provider.name` on decision spans. OpenTelemetry's `error.type` can be `declined`.
- `routr doctor`'s note on an unversioned model now names its provider: "Cloudflare Workers AI does not version this name" (it said "Cloudflare"), and "OpenAI does not version this name".
- Jev's line in the setup menu now says it gets the most levels right on the real tasks in routr's tests (28 of 36). It used to say it reads the level most accurately, which GPT-6 Luna's 85 of 104 now contradicts.

No field is removed or renamed.

## How much of this was run

- **Tests:** `bun test` passes on macOS, Linux and Windows CI. They cover:
  - OpenAI's request shape, and reading its answers back;
  - a refusal that declines, and refusals beside a malformed answer, an answer of an unknown type, or a question routr did not ask, which are unreadable replies and stop the list;
  - repeated names or spread values;
  - a refusal-shaped HTTP error, which is retried and keeps its status.
- **The model gate:** three runs on the saved items, described above. One real API call first confirmed what the reply looks like: score levels count from 0, and `score` is the expected level. OpenAI's `confidence` matched TypeSafe's definition on all 258 levels and 225 choices, so routr keeps it as sent.
- **Live, on macOS:**
  - `routr dispatch` read a brief through GPT-6 Luna, and `routr doctor` showed it answering in 209 and 241 ms;
  - in a throwaway home, `routr setup --yes --decision openai,typesafe` and `routr key set openai` worked, and the saved key file was readable only by its owner.
- **Review:** over three rounds, a read-only reviewer on another subscription found four issues in how OpenAI's replies were read. All are fixed, with tests:
  - a repeated answer could hide an invalid one;
  - a malformed reply holding a refusal moved on instead of stopping;
  - a refusal-shaped HTTP error skipped its retries;
  - an unreadable spread value raised an unclassified error.

  It also found doctor's missing note on the unversioned name, and a stale sentence in the evidence.

  A second reviewer checked the docs against the code and the gate report, and its findings are fixed.
- **Not run live:** GPT-6 Luna on Windows or Linux, and inside a worker launch. What the requests cost is not measured either.
