## Upgrading from 0.5.3

No configuration change is needed. If a Codex worker of yours sat in its pane without starting the task routr said it
sent, that was this; launch it again after upgrading.

## Highlights

- **Codex workers get their task when one of your Codex hooks is new or changed.** Whenever an enabled Codex hook is
  new or changed since you last trusted it (a tool rewriting `~/.codex/hooks.json`, or a repository's own
  `.codex/hooks.json` you never reviewed in Codex), Codex opens "Hooks need review" when it starts. herdr reads that
  screen as idle, so `routr launch` sent the task into it: the task's Enter opened Codex's hooks panel, the task was
  lost, and launch reported the worker as prompted (measured on Codex 0.160.0 and 0.161.0, 2026-10-08). launch now
  passes Codex's own `--dangerously-bypass-hook-trust` beside `--yolo`, and Codex starts at its input box. What that
  means: a worker runs every enabled hook without asking whether it was reviewed, a repository's own hooks included,
  as it already runs any command with `--yolo`. Keep workers away from repositories whose hooks should not run.
- **Codex's folder question comes with how to stop it.** Codex 0.160.0 asks to trust a folder that is not under a
  trusted one even with `--yolo` (0.157.1 did not). launch already handed that question back to the orchestrator;
  it now adds that trusting the repository once in Codex (`codex` in it, then "Trust and continue") means no worker
  in its worktrees is asked again (measured 2026-10-08).

## CLI and JSON compatibility

`routr launch --kind codex` passes one more flag, `--dangerously-bypass-hook-trust`; `--dry-run` shows it. It is in
`codex --help` of every Codex release checked, 0.135.0 to 0.161.0 (older ones not checked). A Codex `needs_input`
at startup now carries a `note`, as Claude's already did. Telemetry payloads are unchanged.
