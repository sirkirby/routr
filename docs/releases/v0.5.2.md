## Upgrading from 0.5.1

No configuration change is needed. If an automatic update has been failing for you with "The operation timed out"
(see `update.log` in routr's cache folder, or `routr doctor`), install 0.5.2 once by hand with the install command from
the README, or run `routr update` on a faster connection; from then on updates work on slow connections too.

## Highlights

- **Updates succeed on slow connections.** Each release download used to have 120 seconds in total, and routr's
  binaries are 59 to 82 MB, so on a connection slower than about 0.5 to 0.7 MB/s `routr update` always failed and the
  daily automatic update failed quietly every day. Measured 2026-10-07: `routr update` timed out three times out of
  three while `curl` fetched the same 62 MB file in 181 seconds. A download now stops only when no data arrives for 30
  seconds, with a 30-minute limit overall.
- **Downloads go straight to disk.** The binary is written to a private temporary file as it arrives and checked
  against the release checksum before it replaces routr, instead of being held in memory. A temporary file left by an
  interrupted update is removed by the next one.

## Verification

Reviewed by an independent worker on another harness: two serious findings (a pre-existing file or link beside routr
could be written through; a partial write to a full disk could pass the checksum) were fixed and verified, with
regression tests. Checked against a local server under Bun and Node. Windows file locking during the swap is covered
by CI tests, not yet on a Windows desktop.

## CLI and JSON compatibility

`routr update` reports a stalled download as "the download of <asset> stalled: no data for 30 s". No other output
changes. Telemetry payloads are unchanged.
