## Upgrading from 0.8.0

No configuration change is needed, and nothing to review in `routr setup`. The orchestrator and setup guides and
`routr usage --help` gained one clause (the usage refresh rule below); nothing an agent does changes, so a session that
already loaded routr need not reread it.

## Upgrading from 0.7.0

Read [Upgrading from 0.7.0](https://github.com/sirkirby/routr/blob/main/docs/releases/v0.8.0.md#upgrading-from-070) in
the v0.8.0 notes first: `routr launch` and `routr cleanup` outside herdr changed in 0.8.0. Then this release's fix
applies: Cursor or Kiro readings that 0.7.0 failed are taken again at the first call.

## Fixed

- **Cursor stayed `unknown` after upgrading from 0.7.0.** Cursor's and Kiro's usage are read in the background about
  once per working session: when the last try is over 4 hours old, a call starts a fresh reading. A failed try by an
  older routr counted too. On a machine where 0.7.0 failed every Cursor read (herdr 0.9.5), `routr usage`, `routr
  dispatch` and `routr setup` under 0.8.0 kept showing Cursor as `unknown` with the assumed headroom (0.5 unless
  `assumed_headroom` is set) for up to 4 hours, while `routr usage cursor` read it at once. Now, when the last try got
  no reading and an older routr made it, the first call after the update starts a fresh reading in the background at
  once (for Cursor, in a private herdr session). That call still shows the old state and says a reading is being
  taken; the next call shows the new reading once it lands, a few seconds later for Cursor and about 10 s for Kiro.
  Each write to the usage snapshot records the routr version that made it.

If Cursor or Kiro still shows `unknown` a minute after the first `routr usage` (or `dispatch`) under this version, run
`routr usage cursor` (or `kiro`): it reads now and its `unavailable` entry says why a reading fails.

## Verification

- Reported on a macOS work machine on 0.8.0 (herdr 0.9.5, a Cursor Team plan): `routr usage` showed Cursor `unknown`
  while `routr usage cursor` read Included 20% used, class `included`. The cause was found in the code and reproduced
  by a test; the fixed build has not been run on that machine.
- Tests: the case reproduced for Cursor and Kiro, with every kind of saved version (none, older, newer, the same, one
  that is not a version), a failed reading after the upgrade, and a source checkout and an installed binary sharing
  one cache (the newer retries once, the older never). `bun test` on macOS, Linux and Windows.
- Review: a routr worker on another model family reviewed the code and docs in one review, and verified the fixes
  three times. The brief and reviews are kept in the maintainer's workbench, not in this repository.
- A test helper that could fail on Windows after its condition had held (seen once in CI) was fixed too.

## CLI and JSON compatibility

Unchanged; nothing new in `--json`. The usage snapshot files in `~/.cache/routr` gain a `by` field (the routr version
that last wrote them). Files without it are read as before, except that a failed try recorded in one no longer holds
back the next background reading (the fix above).
