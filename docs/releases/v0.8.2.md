## Upgrading from 0.8.1

No configuration change is needed, and nothing to review in `routr setup`: no setting is new or changed.

The update reinstalls routr's skills, and the guides changed in this release (below). Nothing a lead or worker must
do differently, but an agent that already loaded routr reads the older wording until it rereads the skill or starts
a new session.

**If you uninstall routr:** finish any headless worker first with `routr cleanup --worker <name>`. Uninstall now stops
and says so while one is there, and `--purge` also stops while a worktree a headless launch made is still under
`~/.local/share/routr/worktrees`.

## Upgrading from 0.7.0

Read [Upgrading from 0.7.0](https://github.com/sirkirby/routr/blob/main/docs/releases/v0.8.0.md#upgrading-from-070) in
the v0.8.0 notes first: `routr launch` and `routr cleanup` outside herdr changed in 0.8.0.

## Fixed

- **`routr uninstall --purge` deleted headless workers' worktrees unchecked.** Since 0.8.0 the git worktrees a
  headless `routr launch --worktree` makes live under `~/.local/share/routr`, which `--purge` removed whole, uncommitted
  work included, with none of cleanup's checks. A plain uninstall left headless workers' run folders and reports in
  `~/.local/state/routr`, and a worker still running was left with no routr to follow or finish it. Now uninstall removes nothing,
  in any mode and in a dry run, while a headless worker's run folder is there, and names the command that finishes
  each (`routr cleanup --worker <name>`); a run folder a launch never finished writing is named by its path to look at.
  With `--purge` it also removes nothing while anything but empty folders is under `worktrees/`, in any layout, and
  names `routr cleanup --cwd <path> --path <path>`, which keeps uncommitted work. A folder it cannot read stops it too.
  Once nothing stops it, it also removes `~/.local/state/routr`.
- **An uninstall and a headless launch at the same moment cannot miss each other.** Uninstall takes a lock before its
  last check and releases it only once the rest of its state folder is gone; a launch that reserves its run folder
  while the lock is held backs out, and one that comes after keeps its folder, which uninstall then keeps and says
  so. A lock left by an uninstall that was stopped is never taken over: uninstall names the file to remove, and
  launches go on.
- **`routr doctor` no longer says orchestration needs herdr.** Without herdr, workers run headless; herdr is needed for
  pane workers and to read Cursor's usage, which is what doctor now says. `--help` for `dispatch` and `subagent` says
  the same.
- **The docs and guides say what 0.8 does.** A sweep of every doc against the code after the headless-worker releases:
  - the README, INSTALL, both skills and the guides describe workers in herdr panes or headless;
  - an orchestrator never runs `routr subagent`, in herdr or not, as the orchestrator guide already said (the skills
    and the `subagent` advice's `next` step said "in herdr");
  - the harness guide records how each usage reader works;
  - `docs/contracts.md` covers the headless commands' states, headlines and warnings;
  - the guarantees, troubleshooting and ranking pages cover uninstall, a headless worker's environment, the
    stale-usage warning, the project `.env` routr no longer loads, and kept readings;
  - `docs/evidence.md` adds the one measurement behind "delegating roughly doubles usage" and says what was not
    measured for headless Claude Code;
  - the README now says three harnesses, not four, were measured following the skill.

## Verification

- Tests: the uninstall cases driven through the CLI (a worker in every mode, `--purge` with a worktree holding an
  uncommitted file, an unfinished run folder, an unreadable folder, a worktree in another layout, the plain uninstall
  keeping it, `--purge` once clear), each interleaving of a launch and an uninstall the review raised, a linked state
  folder, and a stale lock. Each new check fails without its fix. `bun test` on macOS, Linux and Windows.
- By hand on macOS, in a throwaway home with no harnesses: the refusal messages, then a plain uninstall keeping the
  worktree and removing the state folder.
- Reviews: the doc sweep by two routr workers on other model families (an accuracy review against the code and a docs
  audit), with a verification pass on the fixes; the uninstall fix by a routr worker on another model family, with
  seven verification passes until it found nothing more. The briefs and reviews are kept in the maintainer's workbench,
  not in this repository.
- Not measured: uninstall racing a real headless launch (only the interleavings in the tests), and uninstall on
  Windows beyond CI.

## CLI and JSON compatibility

- `routr uninstall` returns `ok: false` with `error` (exit 1) in the cases above, where it used to remove; a dry run
  in those cases does the same. Its successful output is unchanged, and it may list `~/.local/state/routr` as removed,
  or as kept with a reason.
- The `subagent` advice's `next` step reads "An orchestrator, in herdr or not, never runs routr subagent …".
- `routr doctor`'s herdr line and step have new wording. Nothing else in `--json` changes.
- Config, saved advice, the ledger and telemetry: unchanged.
