## In the Herdr app, workers run on their own screen in a tab

In 0.11.0 a lead in the Herdr app started its workers headless and showed their progress in a tab. Now each worker runs its real harness (Claude Code, Codex, Cursor, Antigravity or Kiro) in a tab of its own, in the lead's space, on herdr-core. You see it work and can type into it, and the lead follows it, messages it and reads it with `hc`, as it uses herdr for a pane. The task reaches the worker as a file only it reads, never on its command line. `routr cleanup --worker` ends its tab and removes its worktree.

- **Cursor** reports no status to herdr-core, so its prompt tells it to send its report to the lead's tab with `hc send` when it is done or stuck.
- **Kiro** runs its V3 engine in the app, with `--trust-all-tools`. Kiro asks once whether to run in that mode; choose "Yes, and don't ask again", and later starts ask nothing. In a herdr pane Kiro stays on V2, now named with `--v2`, which also fixes 0.11.0's known issue: a pane worker no longer stops at Kiro's choice between V3 and V2.

## Workers no longer stop at a folder-trust question

Where a harness has its own way to trust a folder for one run, saving nothing, routr now uses it for the worker's folder, in the app and in herdr panes: Codex through its per-run config override, Kiro V3 with `--trust-workspace`, Cursor with `--trust` as before. A headless worker was never asked. That folder's own settings, hooks and MCP servers then load for that run; nothing in your harness settings changes. Claude Code and Antigravity have no such flag: they still ask in a folder you have not trusted, and the lead brings that question to you.

In the app, a worker that has run for 20 seconds without reporting any status is handed back to the lead then, as most likely waiting at a question, instead of after the full launch timeout (2 minutes by default).

## Cleanup in the app sees the tabs

`routr cleanup --cwd`, `--worktree` and `--path` in the app now refuse to remove a worktree while a tab is in it: one that started there, or one whose program is there now. For a worker's tab they name `routr cleanup --worker`, which ends the tab first. `cleanup --worker` makes the same check, passing over its own tab. Once a repository's last worktree is removed, the empty folder it left in routr's worktrees folder goes too.

## Also

- **Cursor's usage without herdr.** On macOS and Linux routr reads Cursor's usage in a terminal of its own, so Cursor's room is known without herdr installed. Windows still reads it in a private herdr session.
- **Setup and doctor know the app.** `routr setup`, `routr doctor` and the guides list the Herdr app as a way to see workers, and doctor no longer tells someone using the app to install the older herdr's skill.
- **One place decides where a worker runs.** Pane, app tab or headless is chosen once, at launch, and recorded with the worker; the later commands act on what was recorded. No behavior changed with this.
- **Folders a pane's shell cannot be given.** In a PowerShell or cmd pane, launch now refuses, before typing anything, a folder path with a typographic quote (‘ ’) in the harness's command, which herdr would type broken; in a fish pane, a path with a backslash before another backslash or a quote, or ending in one. Both were already broken for an Antigravity worker's folder.

## Upgrading from 0.11.0

No setup is needed, and your settings do not change. The update reinstalls routr's skills, and the guides changed a good deal for the app. An agent that already loaded routr reads the older guide until it reads it again or starts a new session.

A lead in a herdr pane works as before, except that Codex and Kiro workers now start trusting their own folder for that run. A lead with neither herdr nor herdr-core works as before.

If you use Kiro in the app, answer its trust-all-tools question once with "Yes, and don't ask again" (it saves `chat.disableTrustAllConfirmation` in Kiro's own settings).

## How much of this was run

Measured on macOS:

- **A real lead in the app**, before the app's 0.1.13 update (hc 0.1.17): a Claude Code lead given `/routr-orchestrate` and a two-task plan launched a Claude Code worker and a Codex worker in tabs beside it, followed them with `hc`, sent one a follow-up with `hc send` (it ran as a second turn of the same session), checked both, merged them, cleaned both up and recorded both. This ran before the trust and cleanup changes below: its Codex worker stopped at the trust question, which is what led to them.
- **All five harnesses** launched in app tabs on one small task each, followed to done, and cleaned up (hc 0.1.17). A Kiro worker in a herdr pane with `--v2`.
- **Folder trust and the 20-second answer**, Herdr app 0.1.13 and hc 0.1.18, in a new repository no harness had trusted: a Codex worker started in about a second and did its task, with `~/.codex/config.toml` unchanged; a Claude Code worker came back to the lead after 20 seconds, its question left for the person, with nothing written. Each harness's first status report was timed directly: Claude Code, Codex and Antigravity within 1 second, Kiro with its folder trusted within 2. Kiro's `--trust-workspace` was measured directly, not through routr.
- **Cursor's usage read** without herdr, from the compiled binary.

Not run: Linux or Windows in the app (the tests run there in CI), a long real task in the app, a lead and a core started with different home folders, Kiro's per-run trust through routr, remote machines (`hc run --on`, which routr does not use).

## What this is not yet

- `routr wait`, `send` and `stop` do not follow a worker in the app: they say so and give the `hc` commands. Reading a finished worker's report from its tab is up to the lead, with `hc read`.
- Cursor's report reaching the lead with `hc send` was measured 3 times of 3 on a small task; on real work it is not measured.
- Kiro says V2 "will be removed in January". Before then, Kiro workers in herdr panes need herdr to recognise V3's questions, or another way; Kiro's usage read still uses V2.

## JSON and output changes

These are additions. Nothing was removed or renamed.

- `launch` in a herdr-core terminal: `worker` is `{ name, backend: "terminal", run, terminal }`; `state` `needs_input` can carry `hc: { state: null, reported: false }` for a worker silent for 20 seconds. `start.argv` shows the per-run trust flags, in a pane too.
- `workers`: a worker in the app gets a row with `backend: "terminal"`, `terminal` and `state: "in_terminal"`. `wait`, `send` and `stop` on one answer with a `terminal_followed` warning and `hc` steps.
- `cleanup`: in the app, `refused` while a tab is in the worktree; an `unavailable` entry with `part: "terminal"` when hc cannot say; a `folder` step when the empty repository folder goes. New warning codes: `terminal_followed`, `terminal_left`, `terminal_status_unknown`, `cleanup_terminals_only`.
- `launch` refuses with a fixed `error` a typographic quote in a PowerShell or cmd pane's command, and, in a fish pane, a backslash fish would read as an escape.
