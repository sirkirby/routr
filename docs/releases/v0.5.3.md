## Upgrading from 0.5.2

No configuration change is needed. If you set `"billing": "metered"` for Claude because routr asked you to after it
reported no usage windows, you can leave it; it now matches what routr reads by itself.

## Highlights

- **routr knows when Claude is billed per token.** It reads how Claude is signed in from Claude's own sign-in check
  (`claude auth status`), which it already runs. A login with an API key is ranked as billed usage (`metered`) by itself,
  instead of routr reporting "no usage windows" and asking you to set `billing`. Measured 2026-10-07: an API-key login
  reports `authMethod: "api_key"`; a subscription login reports `"claude.ai"` with its plan, and its usage windows decide
  as before. Logins through Bedrock, Vertex and other cloud providers, or an API-key helper, are treated the same way,
  from Claude Code's own code and docs (not measured). A `billing` you set yourself still wins.
- **Switching how Claude is signed in shows up right away.** When Claude reports no usage windows, routr checks the
  sign-in again before deciding, so a switch between a subscription and an API key is seen in the next call, and a
  signed-out Claude is left out with what to run.
- **Claude Team seats are no longer treated as unknown.** A Team seat's `/usage` reports the same windows as Max
  (measured), so every quota plan is read the same way.

## Privacy

Only the derived billing class and a fixed reason are kept with routr's cached sign-in answer. The email,
organisation and account ids in Claude's status are never stored, printed or sent.

## CLI and JSON compatibility

A Claude usage row can now have `"class": "metered"` with `"source": "claude auth status"`; `routr doctor --json`
adds `usage_billing`. Telemetry payloads are unchanged.
