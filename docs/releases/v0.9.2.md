## Upgrading from 0.9.1

No configuration change is needed, and nothing to review in `routr setup`: no setting is new or changed.

**If you use Claude Code on a usage-based Claude Enterprise seat:** routr now detects it and ranks it as `metered`.
If you set `"billing": "metered"` on that subscription by hand, you can keep it (it still wins) or remove it.
`routr doctor` no longer asks you to set it.

The update reinstalls routr's skills, and two guides changed:
- the harness reference has the measured Enterprise sign-in and a section on herdr's worktree folders;
- the setup guide says when a Claude Enterprise seat is detected.

An agent that already loaded routr reads the older guides until it rereads the skill or starts a new session.

If you are upgrading from 0.8.3 or earlier, read [Upgrading from 0.8.3](https://github.com/sirkirby/routr/blob/main/docs/releases/v0.9.0.md#upgrading-from-083)
in the v0.9.0 notes first.

## Changed

- **A usage-based Claude Enterprise seat is ranked as `metered`.** Before, Claude on such a seat was `class: "unknown"`
  on an assumed headroom, and `doctor` asked you to set `billing` by hand. The seat has no quota: its `/usage` shows
  no usage windows, only usage credits spent. routr now reads `"subscriptionType": "enterprise"` on a first-party
  `claude.ai` login from `claude auth status` as `metered`, but only when `/usage` answered with no windows:
  - an Enterprise seat with a quota keeps the same plan name, so its windows still decide;
  - a `/usage` read that failed, or an answer that was empty or cut short, stays a failed read, never "no quota";
  - your own `billing` setting still wins.

  routr keeps only the class, a fixed reason and that fixed condition from the sign-in answer, never the email, organisation or ids.

## Fixed

- **An Antigravity worker launched in herdr with `--worktree` starts in its worktree.** routr built Antigravity's
  command before herdr made the worktree, so it started with `--add-dir` set to the main checkout. Antigravity works
  in that folder, not the pane's, so the worker could write into your main checkout. A dry run now shows
  `--add-dir "<worktree-path>"`. Other harnesses, and headless launches, were not affected. (#129, issue #22)
- **`routr cleanup --worktree <branch>` no longer says "nothing to remove" when the worker left its worktree
  detached** (a reviewer that checked out a fetched commit, say). When no worktree is on the branch but a detached
  worktree's folder is the one herdr or a headless launch names for it, cleanup refuses, names that worktree, and
  gives the `routr cleanup --path <folder>` command to run once you've checked it is the worker's. It never removes
  one on its name alone. `cleanup --worker` no longer calls its own detached worktree someone else's. (#127)
- **A config file holding JSON `null`, a list or any value that is not an object** no longer crashes the advice
  commands (`dispatch`, `subagent`, `check`, `assess`), `usage` or `doctor`: it is read as unreadable, and routr answers on the defaults with a note. (#125)
- **`launch --worktree --copy` in a herdr pane** no longer overwrites a file the commit has, or copies through a
  link out of the worktree, as a headless launch already refused. On macOS and Linux, `--copy`, in a pane or headless, also keeps a
  backslash in a file name as part of the name instead of reading it as a folder. A refused copy fails the launch before the worker
  starts, with the cleanup command. (#125)
- **An update whose new binary hangs** no longer blocks every later update as "another routr update is running": its
  version check and skill install now have time limits, and a binary that outlives them is killed. (#125)
- **The OpenTelemetry sender** no longer busy-loops for up to a minute when you set export up again while it is
  sending. (#125)
- **`routr setup`, `routr telemetry on|off` and `routr uninstall`** write `config.json` and Claude's `settings.json`
  whole, keeping their permissions and any link to them (a dotfiles `settings.json`, say), so another command never
  reads them half written. routr's telemetry state, `telemetry.log` and `update.log` are written whole too. (#125)
- **`routr usage --level`** with an unknown level lists only the real levels. (#125)

## Verification

- `bun test` on macOS, Linux and Windows. Each fix has a regression test that failed on the code before it, except
  one test for #125's link handling, which guards against a regression that change could otherwise have caused. The
  test that a hung update binary is killed runs on all three platforms.
- Review: every change had an independent review by a routr worker on another model family and a docs audit, then a
  verification pass on the fixes. All findings were fixed.
- By hand on Windows 11 (a VM, a binary built from these changes): config.json written whole, through an absolute
  link, through a dangling relative link, and refused for a loop of links; a file held open by another process fails
  the write whole, leaving no temporary files; a hung binary is killed at the limit.
- The Enterprise reading was measured on a real usage-based Enterprise seat on 2026-10-27 (Claude Code 2.1.311,
  macOS): `claude auth status` and `/usage` as described above. Then, with a fake `claude` answering the same way in a
  throwaway home, routr read it as `metered`; an Enterprise seat with windows as `included`, and a Team seat without
  windows as `unknown`, as before. Not measured: an Enterprise seat with a quota (from Anthropic's docs).
- The Antigravity fix, live in herdr: a launch with `--worktree` started the real `agy` with `--add-dir` in herdr's
  worktree folder, where it had pointed at the main checkout before.
- Not measured: a hung update binary on a real user's machine (the tests use a stand-in binary).

## CLI and JSON compatibility

No field or flag was removed or renamed.
- **`usage`, `dispatch` and `doctor --json`:** a usage-based Claude Enterprise seat has `class: "metered"`,
  `usage: "metered"` and `headroom` and `usable` null, where it had `class: "unknown"` and `usage: "assumed"` on the
  assumed headroom. In `doctor --json`, `harnesses.claude` has `usage_class: "metered"` and
  `usage_source: "claude auth status"`, and no `usage_reason` or next step. A Claude `/usage` answer that exited
  non-zero, was empty, was not marked a success, or had a usage line routr could not read is now a failed read
  (`no_response` or `invalid_response` in `unavailable`), where it counted as "no usage windows".
- **`cleanup --worktree`:** a new refusal, for a detached worktree named for the branch, carrying `worktree` (when
  exactly one matches) and a `next` step with the `--path` command for each, where it answered ok with `absent`.
  **`cleanup --worker`** on its own detached worktree says what the worktree holds is not checked, instead of calling
  it not the one launch made.
- **`launch --kind agy --worktree` in herdr:** `start.argv` carries the worktree's path in place of the repository
  path; on a dry run, or when launch fails before herdr makes the worktree, it shows `<worktree-path>`, as
  `would_run` does.
- **`launch --worktree --copy` in herdr:** a new failure (`ok: false`, `state: "failed"`) before the worker's pane
  opens, when a copy would overwrite a file the worktree has or go through a link, with the cleanup command in
  `error` and `next`; it used to answer ok after overwriting or following the link.
- **`usage --level`:** the refusal for an unknown or repeated level lists `basic, standard, strong, given once`.
