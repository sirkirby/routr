## A headless Codex worker's subagent no longer ends its turn

This applies to headless Codex workers: the ones `routr launch` starts outside a herdr pane and outside the Herdr app, followed with `routr wait`. Codex workers in a pane or a Herdr app terminal, and headless workers of every other harness, are not affected.

routr runs a headless Codex worker through `codex app-server`. A subagent the worker starts is a thread of its own on that same connection, and its turn's start, items and end arrive beside the worker's. routr read them all as the worker's, so in 0.18.0 and earlier:

- the subagent's turn ending was taken as the worker's turn ending, so `routr wait` could report the worker finished while it was still working;
- the subagent's final answer could become the worker's report.

Nothing flagged either one.

routr now reads only the worker's own thread as its turn and its report. Another thread's lines count only as signs of activity, so a worker whose subagent is busy does not look idle.

Other harnesses end a turn when the harness says the main agent is done: a `result` from Claude Code, Cursor and Antigravity, and the answer to routr's own prompt from Kiro. A subagent there cannot end the worker's turn. Whether a Cursor or Kiro subagent's text can reach the worker's report has not been measured.

Thanks to @TeknoCentral for finding and fixing this.

## Upgrading from 0.18.0

No setup is needed, and your settings do not change. The update reinstalls routr's skills; the harness reference adds one line on Codex subagent threads.

A headless Codex worker that was already running when you updated keeps the reading it started with until it ends. Workers launched after the update get the fix.

## JSON and output changes

None. No field is added, removed or renamed. A headless Codex worker's `turns` in `routr wait` now count only the worker's own turns, never a subagent's.

## How much of this was run

- **Tests:** `bun test` passes on macOS, Linux and Windows CI. A new test feeds routr a subagent's turn and answer in the middle of the worker's turn. It fails without the fix.
- **Live, Codex 0.169.0 on macOS:** one real app-server turn whose task told Codex to start a subagent. The subagent's turn ended first, on its own thread. Replayed through each version of routr's reader, 0.18.0 took the subagent's answer as the report, and this release took only the worker's own.
- **Live, Codex 0.171.0**, by the contributor: a headless Codex worker that started a subagent finished in one turn, twice.
- **Not measured:** subagents on Cursor or Kiro.
