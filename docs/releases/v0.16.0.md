## OpenTelemetry export names the lead's session in the standard attribute

This applies only if you turned on OpenTelemetry export (`routr setup --otel-endpoint`). Export stays off unless you configure it.

The `routr dispatch`, `routr subagent`, `routr launch` and `routr send` spans now carry the lead's session id as `gen_ai.conversation.id`, because each of these commands runs inside the lead's conversation. The attribute `routr.lead.session_id` is gone. A receiver that reads only standard OpenTelemetry and GenAI attributes can now tell which session started a worker. `send` reads the lead's id from the harness environment only; `--lead-session` still applies to `dispatch`, `subagent` and `launch`.

In 0.15.0, `gen_ai.conversation.id` on a `launch` or `cleanup` span held the pane worker's conversation id, as herdr reported it. The lead's id was in `routr.lead.session_id`.

## A pane or terminal worker's task gets its own span

When a worker in a herdr pane, or in a tab of the Herdr app, takes its launch task, routr records a CLIENT child span `invoke_agent <worker name>` under the launch span. When a Herdr app worker takes a message from `routr send`, routr records the same child under the send span. Either span marks another program, not a person, giving that worker an instruction. It starts when routr hands the instruction over and ends when the command has its answer.

The span carries:
- the worker's own repository, branch, cwd and worktree;
- `gen_ai.operation.name=invoke_agent`, the harness platform, the worker's name, harness kind, backend and launch id;
- the model and effort as given, except for an agent that a `--pane` recovery rerun adopted, which kept its own settings;
- in a herdr pane, the worker's conversation id when herdr has reported it by the end of the launch.

A Herdr app worker's conversation id is never known: a receiver can match the span to that harness's session by repository, branch and time. A lead talks to a pane worker through herdr itself, so routr sees only its launch task, not later messages.

`routr cleanup` no longer carries a conversation id; it still links to its launch. Headless workers are unchanged: their holder records one `invoke_agent` span per turn, and `send` adds none.

## A harness you have just signed in to is seen at once

After you signed in to a harness that routr had found signed out, `routr usage`, `dispatch` and `launch` kept leaving it out as "not signed in" for up to 10 minutes. A "not signed in" answer is no longer kept: routr asks the harness's own status command again each time, in parallel with the others; it took 0.3 to 3.4 s. A signed-in answer is still kept 6 hours. When there was no answer (not installed, or the check hung), that is still kept 10 minutes, so a hanging check does not cost its 15 s timeout on every command. `routr board`, `top` and the statusline call no harness, as before: they show the kept answer until the next `usage`, `dispatch` or `launch` asks again.

## Upgrading from 0.15.0

No setup is needed, and your settings do not change. The update reinstalls routr's skills. The orchestrator guide's trace context section and the harness reference's trace notes now describe the new spans. An agent that already loaded routr reads the older guides until it reads them again or starts a new session.

If an OpenTelemetry receiver or dashboard of yours reads `routr.lead.session_id`, read `gen_ai.conversation.id` on the command span instead. A worker's conversation id now appears only on an `invoke_agent` span.

## JSON and output changes

No command's JSON answer changes. The exported OpenTelemetry signals change as described above: `docs/opentelemetry.md` lists every span and attribute.

## How much of this was run

- **Tests:** `bun test` passes on macOS, Linux and Windows CI. The trace tests run fixture pane and terminal launches and a terminal `send`. They check each new span's parent, kind, timing, attributes and conversation id. They also check that a dry run, a failed launch, a launch turned away and a headless `send` add none, and that the new span stays inside its parent when the wall clock jumps an hour either way.
- **`bun run smoke:otel`** passed against a local receiver, outside herdr; its pane case was skipped there.
- **Review:** the change was reviewed by two read-only workers on other subscriptions, one on the code and one on the docs, and the code reviewer verified the fixes. The two code findings were an adopted agent's model and effort, and the span's clock. Both are fixed, with regression tests.
- **Not run live:** a real pane or Herdr app worker exporting to a receiver. The sign-in problem was seen live with Cursor on 2026-11-19; the change is covered by tests.
