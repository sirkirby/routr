## Upgrading from 0.4.2

No configuration migration is required. Your subscriptions, models, effort, account-use preferences, work-level
limits, reserves and update channel are preserved, and setup has no new required choices.

The update installs a second skill, `routr-orchestrate`, beside `routr`, and links both into Antigravity's skills
folder as well. Ask an agent that already loaded routr to reread the skill, or start a new session.

If you set `routr statusline` as Claude Code's statusline, it keeps working and routr still uses its reading while it
is fresh; you can also remove it, as routr no longer needs it. If you have your own statusline, routr now reads your
Claude usage anyway.

## Highlights

- **Claude Code's usage is read from Claude itself.** routr runs `claude -p /usage`, which Claude answers locally (no
  model turn, no tokens), instead of depending on owning Claude's statusline. Anyone with their own statusline used to
  get an assumed 50% headroom. routr's read runs with your hooks and MCP servers switched off for that one run, leaves
  no files behind, and setup no longer installs the statusline.
- **Start an orchestration with `/routr-orchestrate <your plan>`** (Codex: `$routr-orchestrate`). The session becomes
  the routr orchestrator and sends every handoff through routr. It is meant to be typed by you, not chosen by the
  model: measured hidden from the model in Claude Code, Codex, Cursor (CLI) and Antigravity; listed in Kiro, where its
  description is the guard.
- **npm-installed harnesses work on Windows.** routr resolves commands the way a shell does and starts an npm shim's
  script directly, so a harness installed through npm (such as Codex) is found and used.
- **Antigravity gets routr's skills** (it reads `~/.gemini/config/skills`, measured).
- **`routr launch`:** running `then` right after answering a worker's startup question hands it its task when herdr
  already reads it ready; a busy worker is never given a second task.
- **`routr doctor` makes no network call.** It shows what the daily update check saw.
- **Safer installs and updates:** skill installs and uninstall touch only routr's own files (each skill folder carries a
  manifest); updates cannot step back to an older version; timed-out reads always end, on every platform.

## Verification

Every change was reviewed by an independent worker on another harness, then reviewed again as a whole before this
release, with each finding fixed and verified. Windows behaviour was checked on Windows CI; testing on a Windows
desktop through the betas is ongoing and has gone well so far. Claude Team, Enterprise and API-key seats are not yet
observed. Reports are welcome: `routr feedback "<text>"`.

## CLI and JSON compatibility

A Claude usage row can have `"source": "claude /usage"`; its windows keep the names `five_hour` and `seven_day`.
`routr launch` `needs_input` may carry `herdr.explained`. `routr doctor --json` adds `update_seen_hours_ago` and lists
each skill with where it is installed. `routr skill install`, `uninstall` and `update` report folders they left alone
(`kept`) and exit 1 when a step fails. `routr setup --no-statusline` is accepted and does nothing. Telemetry payloads
are unchanged.
